# 为什么一句话做不出好片子

同一个模型（Opus 5.5，在 Claude Code 里），同一个题目（国庆坐高铁回家），前后做了 5 版，花了 6 个多小时：

![v2 / v3 / v5 / v6 同一场景对比](v2-v6-compare.jpg)

左上 v2 → 右上 v3 → 左下 v5 → 右下 v6。

| 版本 | 做了什么 | 问题 / 结论 |
|---|---|---|
| v1 | 一次写完：SVG 纯色块，车窗外景物横向滚动，一站一个地名 | 能跑，但像 PPT；没有故事 |
| v2 | 在 v1 上加特效：镜头晃动、动态模糊、对面驶过的列车、隧道闪光 | 特效堆上去了，底子还是纯色块，依然像 PPT |
| v3 | 推倒重来，**先只画 3 张风格帧**：Canvas 2D，逆光、雾、光束、泛光、颗粒 | 质感上来了，先给人看、再动手 |
| v5 | 测试 Three.js 3D：天空着色器、水面反射、雾、桥和列车；改了 3 轮 | 镜头能真正运动；第一轮像十年前的游戏，调色和构图后才能用 |
| v6 | 2D 车窗 ＋ 3D 航拍，故事改成“妈妈的消息”，配乐重编 | 成片 |

差别不在模型，在流程：

1. **没有故事，画得再好也只是屏保。**v1 的问题从一开始就不是画面。
2. **先定风格帧，再做动画。**v1→v2 在错误的底子上加特效，白做一轮；v3 只画 3 张图就看出了方向。
3. **路线要早比。**同一场景用 2D、3D 各画一张放在一起看，比在一条路上死磕省时间。
4. **自检要看“好不好看”，不只是“有没有报错”。**技术检查全过的 v2，一样被否。

这个仓库的 `SKILL.md` 就是把上面这几条变成固定步骤。
